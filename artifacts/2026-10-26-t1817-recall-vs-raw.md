# T-1817: claim recall vs raw transcript RAG

## Setup

- 40 questions (18 single-fact, 22 relational), one seed, top-5 retrieval.
- Questions were generated from recent transcripts with exact-source validation (evidence index within +-3 messages of the cited one, privacy and token-overlap checks).
- Answer and judge model: Claude Haiku. The judge uses the gold answer only as the criterion.
- Arms: (a) claim recall, (b) dense retrieval + cross-encoder rerank over raw transcript chunks, (c) interleaved union of a and b.
- The claim DB is opened read-only. No questions, session ids, paths or project names are stored in this repository.

## Results

| Arm | Evidence hit@5 | Answer correctness | Mean context tokens | Mean retrieval ms |
|---|---:|---:|---:|---:|
| a. Claim recall | 0.00 (see coverage note) | 0.05 | 726 | 210 |
| b. Dense + rerank over raw chunks | 0.40 | 0.30 | 17,211 | 218 |
| c. Interleaved union | 0.30 | 0.225 | 8,233 | 218 |

| Category | n | a hit@5 / correct | b hit@5 / correct | c hit@5 / correct |
|---|---:|---:|---:|---:|
| Single-fact | 18 | 0.00 / 0.111 | 0.278 / 0.222 | 0.167 / 0.167 |
| Relational | 22 | 0.00 / 0.000 | 0.500 / 0.364 | 0.409 / 0.273 |

## Coverage check (read-only)

The 40 gold questions come from 7 sessions. Zero claims in the DB cite any of them. In capture-control, 5 of the 7 sessions are in state `captured` (never extracted, part of the ~1,000-capture backlog) and 2 were never captured.

So arm (a) hit@5 = 0 is a coverage fact, not a ranking failure: the facts never reached memory. Arm (a)'s correctness (2/40) came from older, related claims.

## Interpretation

1. Raw dense + rerank over recent sessions works (0.30 correct), at about 24x the context tokens of claim recall.
2. This run cannot judge claim-recall quality, because the questions' facts were never extracted. It measures the extraction backlog.
3. c < b is an interleave artifact (claims take raw slots at k=5), not evidence against combining.

## Recommendation

No production change yet. Two numbers decide it: rerun the same harness after the T-1805 extractor and a backlog drain (claims covering these sessions exist), then compare a vs b.

Meanwhile, a raw-evidence path over the last N days of transcripts is the cheap bridge for exactly the gap measured here (recent, unextracted sessions). Propose it as a scoped card: recall-time only, budgeted tokens, behind a flag.

## How to rerun

```
python scripts/bench_recall_vs_raw.py build --out <questions.json> [--seed 1817] [--opencode opencode] [--candidate-model <model>]
python scripts/bench_recall_vs_raw.py run --db <claims.db> --questions <questions.json> --out <results-dir> [--answer-model haiku] [--judge-model haiku]
```

- `build` asks the candidate model over up to 8 batches of 50 transcript chunks, validates each item against the source, and prints rejection counts to stderr. It needs at least 25 approved (warns below 30).
- `run` loads cached local MiniLM embedding and cross-encoder models offline, opens the DB with SQLite `mode=ro`, and writes `details.json` plus a printed summary. It checkpoints each question to `<results-dir>.partial.jsonl` and resumes from it; delete that file before a fresh run.
- The harness persists question ids and aggregate outcomes only, not retrieved context or model answers.
